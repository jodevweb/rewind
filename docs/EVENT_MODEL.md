# REWIND — Event Model

> STEP 5 deliverable (§150). The canonical schema. Defined once in `packages/protocol` as JSON Schema
> and generated into Rust and TypeScript, so the daemon, the extensions and the UI cannot drift apart.

---

## 1. The ladder

Every layer is derived from the one below and keeps a link back to it. Nothing higher up is ever
asserted without something lower down to cite (§54, §159).

```
RawEvent          what a collector observed
   ↓ normalise
TimelineEvent     canonical, redacted, enriched, scored
   ↓ group
Activity          a contiguous run of related events  (minutes)
   ↓ sessionise
Session           a work stretch bounded by idle / lock / project switch  (hours)
   ↓ infer
Context           what the user was actually working on  (the product)
   ↓ extract
Decision / Outcome  what was concluded or produced
```

## 2. TimelineEvent

The spec's §21 draft, tightened. Changes from §21 are listed in §2.3 with reasons.

```ts
interface TimelineEvent {
  /** UUIDv7 — time-ordered, generated by the producer, used for idempotent ingest. */
  id: string;

  /** Epoch milliseconds, UTC. */
  timestamp: number;
  /** Epoch milliseconds, UTC. Present for events with duration (focus, command, session). */
  endTimestamp?: number;
  /** Local UTC offset in minutes at capture time. Required for temporal queries (TR-8). */
  tzOffsetMinutes: number;

  source: EventSource;
  /** Namespaced: "system.window.focus", "git.commit", "terminal.command". */
  type: string;

  /** Producer identity, for debugging and trust decisions. */
  producer: { name: string; version: string };

  app?: string; // process/executable name
  appDisplay?: string; // human name
  title?: string; // redacted; sensitive by default (PRIVACY §3.3)

  projectId?: string;
  repositoryId?: string;

  /** Type-specific payload, validated per event type. */
  metadata: Record<string, unknown>;

  privacyLevel: PrivacyLevel;
  /** Proof that redaction ran. Persistence rejects events without it. */
  redaction: RedactionStamp;

  /** Concatenated redacted text for FTS5. Built by the normaliser, never by a producer. */
  searchableText?: string;

  /** 0..100. Drives noise reduction, retention and Resume ordering (§67). */
  importance: number;

  /**
   * Distinctive identifiers extracted from this event: issue ids, project and document names,
   * branches, worktrees, URL hosts, recurring keywords. The primary grouping signal (ADR 0002 D-14).
   * Extracted by the normaliser, never supplied by a producer — except Level 2 sources, which may
   * declare anchors explicitly and are trusted about their own domain.
   */
  anchors: ContextAnchor[];

  /** Assigned by the context engine, not by the collector. Nullable and revisable. */
  activityId?: string;
  contextId?: string;
}

type EventSource =
  | 'system'
  | 'browser'
  | 'ide'
  | 'filesystem'
  | 'git'
  | 'terminal'
  | 'agent'
  | 'external'
  | 'manual';

type PrivacyLevel = 'normal' | 'sensitive' | 'private';

interface RedactionStamp {
  /** Version of the pattern registry that ran. */
  patternsVersion: string;
  /** Detector ids that fired, e.g. ["stripe_secret_key", "env_assignment"]. Never the values. */
  applied: string[];
  count: number;
}
```

### 2.0 Context anchors

```ts
interface ContextAnchor {
  type: 'issue' | 'project' | 'repository' | 'branch' | 'worktree' | 'document' | 'url' | 'keyword';
  value: string; // "DNM-4218"
  normalizedValue: string; // "dnm-4218" — what comparison uses
  confidence: number; // 0..1
  source: 'window_title' | 'url' | 'branch' | 'agent' | 'external' | 'note' | 'path';
}
```

Anchors are what let a Slack window, a Linear window, a Figma document, a Git branch and a Cockpit
mission be recognised as one piece of work. Extracted at normalisation step 6; they drive context
assignment (CONTEXT_ENGINE §4.0) and are the reason the engine works for non-developer contexts at all.

### 2.1 Privacy levels

| Level       | Meaning                                                       | Stored      | Indexed | Eligible for a cloud AI prompt              |
| ----------- | ------------------------------------------------------------- | ----------- | ------- | ------------------------------------------- |
| `normal`    | Ordinary work signal                                          | Yes         | Yes     | Yes                                         |
| `sensitive` | May contain personal or third-party data — most window titles | Yes         | Yes     | Only with explicit per-request confirmation |
| `private`   | User marked it, or it came from a `redact`-rule source        | Yes, masked | No      | **Never**                                   |

Anything matching an `ignore` rule has no level, because it never becomes an event at all.

### 2.2 Importance (§67)

`importance` is computed by the normaliser from a documented, testable table — not a model:

| Signal                                            | Score |
| ------------------------------------------------- | ----- |
| Failed command (non-zero exit)                    | 95    |
| Git commit                                        | 90    |
| Manual note / bookmark                            | 90    |
| Error surfaced in IDE or terminal                 | 85    |
| Branch checkout / merge                           | 80    |
| File save in a tracked repo                       | 70    |
| Terminal command (success)                        | 65    |
| Documentation or issue-tracker URL visited > 30 s | 60    |
| IDE file open                                     | 45    |
| Browser navigation, dwell 5–30 s                  | 35    |
| Window focus > 60 s                               | 30    |
| Window focus 5–60 s                               | 15    |
| Window focus < 5 s, background tab, auto-refresh  | 5     |

Importance decides what survives compaction (§40), what Resume shows first, and what search boosts. It
never decides what is _captured_ — that is the privacy filter's job, and mixing the two would make
capture depend on a heuristic.

### 2.3 Deviations from the §21 draft

| Change                               | Why                                                                       |
| ------------------------------------ | ------------------------------------------------------------------------- |
| Added `tzOffsetMinutes`              | "Last Friday" is unanswerable without it after travel or DST (TR-8)       |
| Added `producer`                     | Needed to debug a misbehaving extension version and to reason about trust |
| Added `redaction` stamp              | Makes fail-closed persistence enforceable rather than aspirational (TR-9) |
| Added `importance`                   | §67 requires it; it belongs on the event, computed once                   |
| Added `activityId`                   | §22 needs a layer between event and context                               |
| `id` is UUIDv7, producer-generated   | Idempotent retry after an MV3 worker eviction (TR-11)                     |
| `searchableText` is normaliser-owned | A producer could otherwise smuggle unredacted text into the index         |

## 3. Event catalogue

`metadata` is validated per `type`. Unknown types are rejected at ingest, not stored "just in case".

### 3.0 Level 1 and Level 2 (ADR 0002 D-13)

Every event is one of two kinds, and the distinction matters more than its source:

- **Level 1 — generic application observation.** Available for _any_ application with no connector at
  all: bundle identifier, window title, activation and deactivation. Most `system.*` events. This is
  the foundation, and the MVP has to prove it is sufficient on its own.
- **Level 2 — rich integration.** A source that understands its own domain and can declare structure:
  `git.*`, `terminal.*`, `agent.*`, `external.*`, and later Linear. These may declare `anchors`
  explicitly instead of having them inferred from a title.

The engine must degrade to Level 1 everywhere. A context assembled only from window titles is a worse
context, never a missing one.

### 3.1 `system`

| Type                                    | metadata                                     | Notes                                                                                                                                     |
| --------------------------------------- | -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `system.window.focus`                   | `{ bundleId, pid, exePath?, monitorCount? }` | Has `endTimestamp`; **the** workhorse event — on macOS it carries the bundle identifier, and its title is often the only signal available |
| `system.window.title_changed`           | `{ previousTitle? }`                         | Coalesced hard — editors change titles constantly                                                                                         |
| `system.idle.start` / `system.idle.end` | `{ idleSeconds }`                            | Bounds sessions (§69)                                                                                                                     |
| `system.session.lock` / `unlock`        | `{}`                                         | Hard session boundary (§70)                                                                                                               |
| `system.power.sleep` / `wake`           | `{ onBattery? }`                             | Hard session boundary                                                                                                                     |
| `system.capture.paused` / `resumed`     | `{ durationMs?, reason }`                    | Persisted; enforces PRIVACY §5                                                                                                            |

### 3.2 `browser`

| Type                    | metadata                                          |
| ----------------------- | ------------------------------------------------- |
| `browser.tab.activated` | `{ tabId, url, host, urlHash, incognito: false }` |
| `browser.tab.opened`    | `{ tabId, url, host, openerTabId? }`              |
| `browser.tab.closed`    | `{ tabId, dwellMs }`                              |
| `browser.navigation`    | `{ tabId, url, host, transition, referrerHost? }` |

`url` is post-policy: `userinfo` stripped, fragment dropped, query stripped unless the host is on the
keep-query allowlist. `urlHash` is a stable hash of the _full_ original URL so the same page is
recognised across visits without storing the parameters.

`incognito` exists in the schema only so ingest can assert it is `false` and reject if not.

### 3.3 `ide`

| Type                              | metadata                                            |
| --------------------------------- | --------------------------------------------------- |
| `ide.workspace.opened` / `closed` | `{ workspacePath, folders[], ideName, ideVersion }` |
| `ide.file.opened`                 | `{ path, languageId, repoRelativePath? }`           |
| `ide.file.saved`                  | `{ path, languageId, lineCount?, changedLines? }`   |
| `ide.file.closed`                 | `{ path, dwellMs }`                                 |
| `ide.diagnostic.error`            | `{ path, line, severity, code?, messageRedacted }`  |
| `ide.debug.session`               | `{ configName, outcome }`                           |

Never file contents (§13). `changedLines` is a count, not a diff. `messageRedacted` is a compiler/linter
message — high value for "what was failing", and redacted because messages quote source lines.

### 3.4 `filesystem`

| Type                                       | metadata                                                 |
| ------------------------------------------ | -------------------------------------------------------- |
| `fs.file.created` / `modified` / `deleted` | `{ path, sizeBytes?, extension }`                        |
| `fs.file.renamed`                          | `{ fromPath, toPath }`                                   |
| `fs.batch`                                 | `{ paths[], count, changeTypes[] }` — the coalesced form |

Coalescing (§14): a 3-second debounce per directory; more than 5 changes in a window collapses to one
`fs.batch`. Ignore-globs from PRIVACY §3.2 are applied in the watcher, before the event exists.

### 3.5 `git`

| Type                             | metadata                                                                        |
| -------------------------------- | ------------------------------------------------------------------------------- |
| `git.commit`                     | `{ sha, messageRedacted, filesChanged[], insertions, deletions, authorIsUser }` |
| `git.branch.checkout`            | `{ from, to, isNewBranch }`                                                     |
| `git.merge` / `rebase` / `stash` | `{ target, conflicted? }`                                                       |
| `git.repo.detected`              | `{ path, remoteUrl, defaultBranch }`                                            |
| `git.status.summary`             | `{ dirtyFiles, ahead, behind, branch }`                                         |

Never diff contents. `filesChanged` is paths only. Commit SHAs are permanent evidence and are exempt
from entropy redaction (TR-10) and from retention deletion (PRIVACY §9).

### 3.6 `terminal`

| Type                   | metadata                                                                        |
| ---------------------- | ------------------------------------------------------------------------------- |
| `terminal.command`     | `{ commandRedacted, cwd, exitCode, durationMs, shell, repositoryId? }`          |
| `terminal.error_tail`  | `{ lines[], lineCount, truncated }` — only on non-zero exit, off unless enabled |
| `terminal.cwd_changed` | `{ from, to }`                                                                  |

The single most secret-dense source in the product. Redaction is mandatory and fail-closed here above
all (PRIVACY §4.2). Full stdout is never captured (§17).

### 3.7 `agent` (schema now, collector post-MVP)

| Type                              | metadata                                            |
| --------------------------------- | --------------------------------------------------- |
| `agent.session.started` / `ended` | `{ agent, model?, projectPath, durationMs? }`       |
| `agent.activity`                  | `{ agent, toolCallCount, filesTouched[], outcome }` |

Metadata only. No prompts, no completions, no tool arguments (PRIVACY PVR-6).

### 3.7b `external` (ADR 0002 D-17)

A generic protocol any authorised local application can emit. Cockpit is the first consumer, not the
coupling.

| Type                                     | metadata                                                |
| ---------------------------------------- | ------------------------------------------------------- |
| `external.mission.started` / `.updated`  | `{ source, missionId, mission, project?, anchors[] }`   |
| `external.agent.started` / `.finished`   | `{ source, missionId, agent, worktree?, status? }`      |
| `external.run.started` / `.finished`     | `{ source, missionId, runId, status, filesChanged[]? }` |
| `external.worktree.created` / `.changed` | `{ source, path, branch?, repositoryId? }`              |
| `external.context.metadata`              | `{ source, anchors[], label?, url? }`                   |

`source` identifies the emitting application and is bound to its pairing token — an application cannot
emit events attributed to another. Anchors declared here are trusted at high confidence, because the
emitter knows its own domain better than any title parser ever will.

### 3.8 `manual`

| Type                              | metadata                                                       |
| --------------------------------- | -------------------------------------------------------------- |
| `manual.note`                     | `{ text, contextId? }` — importance 90, never auto-deleted     |
| `manual.bookmark`                 | `{ target, targetType }`                                       |
| `manual.context.started`          | `{ name, projectId? }`                                         |
| `manual.context.merged` / `split` | `{ sourceIds[], resultIds[] }` — feeds the feedback loop (§32) |

## 4. Normalisation

Between a producer and the store, every event passes through, in order:

1. **Pause check** — reject if the timestamp falls in a recorded pause interval (PRIVACY §5).
2. **Privacy rules** — `ignore` drops it entirely; `redact` lowers `privacyLevel`.
3. **Redaction** — all text fields; stamp applied; on error, drop.
4. **Canonicalisation** — paths to absolute + normalised separators; URLs to policy form; app names
   mapped through a known-app table.
5. **Coalescing** — see §5.
6. **Enrichment** — attach `projectId` and `repositoryId` by longest-prefix path match; attach
   `repositoryId` to browser events when the URL is a code host for a known repo.
7. **Importance** — from the §2.2 table.
8. **`searchableText`** — assembled from redacted title, path basename, URL host + path, command,
   commit message.
9. **Validation** — schema check for the type; on failure, log and drop (never store a malformed event).

Steps 1–3 are the privacy boundary. Nothing downstream may re-widen it.

## 5. Coalescing rules (§68)

| Pattern                               | Rule                                                            |
| ------------------------------------- | --------------------------------------------------------------- |
| Repeated focus on the same window     | Extend `endTimestamp` instead of a new event, if the gap < 30 s |
| Title churn in one app                | One `title_changed` per 10 s, keeping the last                  |
| Rapid file saves, same file           | One `ide.file.saved` per 30 s per path                          |
| Filesystem storms                     | `fs.batch` after 5 changes in 3 s per directory                 |
| Tab switching under 5 s               | Dropped unless it is the last before a longer dwell             |
| Background tab auto-refresh           | Dropped (`transition == "reload"` with no focus)                |
| Build artefacts, `node_modules`, temp | Dropped in the watcher                                          |

Target: about 6 100 raw signals per day become about 1 800 stored events (TR-13). Coalescing is
measured, not assumed — the debug panel shows the ratio live.

## 6. Activity

```ts
interface Activity {
  id: string;
  startTimestamp: number;
  endTimestamp: number;
  tzOffsetMinutes: number;

  label: string; // derived, human-readable: "Editing stripe.webhook.ts"
  primarySource: EventSource;
  eventIds: string[];
  eventCount: number;

  projectId?: string;
  repositoryId?: string;

  apps: string[];
  files: string[];
  urls: string[];
  commands: string[];

  importance: number; // max of members, damped by duration
  embedding?: Float32Array; // computed here, never on raw events (TR-6)
  sessionId?: string;
  contextId?: string;
}
```

An Activity is a contiguous run of related events, typically 1–15 minutes (§22). It is the first level
at which a human sentence is attachable, and the first level that gets an embedding.

## 7. Session

```ts
interface Session {
  id: string;
  startTimestamp: number;
  endTimestamp: number;
  tzOffsetMinutes: number;
  workDay: string; // "2026-08-28", using the 04:00 local cutoff (TR-8)

  activityIds: string[];
  idleMs: number; // excluded from durations (§69)
  boundaryReason: 'idle' | 'lock' | 'sleep' | 'project_switch' | 'manual' | 'day_cutoff';

  projectIds: string[];
  contextIds: string[];
}
```

A session is a stretch of continuous work (§23). Sessions bound _time_; contexts bound _meaning_. One
session can hold several contexts, and one context spans many sessions — which is exactly why both
exist.

## 8. Context

The product's central object (§24).

```ts
interface Context {
  id: string;
  name: string; // "Stripe renewal bug" — inferred, user-editable
  status: 'active' | 'dormant' | 'resolved' | 'archived';

  createdAt: number;
  lastActiveAt: number;
  totalActiveMs: number; // idle excluded

  projectId?: string;
  repositoryIds: string[];

  activityIds: string[];
  sessionIds: string[];

  summary?: ContextSummary;
  links: ContextLink[]; // the graph edges (§25)

  confidence: number; // 0..1 — how sure the engine is this is one thing
  origin: 'inferred' | 'manual' | 'merged' | 'split';
  correctionCount: number; // feeds §128 quality metrics

  embedding?: Float32Array;
}

interface ContextSummary {
  text: string;
  nextStep?: string;
  generatedAt: number;
  generatedBy: 'deterministic' | 'llm';
  model?: string;
  promptVersion?: string;
  confidence: 'high' | 'medium' | 'low';
  evidenceIds: string[]; // never empty (§54)
}
```

`generatedBy: "deterministic"` is the default and must be genuinely useful on its own (PR-2). A summary
with an empty `evidenceIds` is invalid and is rejected.

## 9. Context links (§25)

```ts
interface ContextLink {
  contextId: string;
  targetType:
    | 'file'
    | 'url'
    | 'commit'
    | 'command'
    | 'error'
    | 'decision'
    | 'task'
    | 'agent_session'
    | 'note';
  targetKey: string; // path, canonical URL, SHA, command hash, ticket id
  relationship:
    | 'modified'
    | 'read'
    | 'researched'
    | 'produced'
    | 'investigated'
    | 'resulted_in'
    | 'referenced'
    | 'failed_in';
  firstSeenAt: number;
  lastSeenAt: number;
  occurrences: number;
  weight: number; // 0..1, from occurrences × importance × recency
  evidenceIds: string[];
}
```

These are the rows that make "why does this exist?" answerable, and they are **permanent** — links
survive raw-event compaction (TR-5, PRIVACY §9), because they _are_ the citable evidence.

## 10. Decision and Outcome (§53)

```ts
interface Decision {
  id: string;
  contextId: string;
  statement: string; // "Use invoice.created as reconciliation fallback"
  madeAt: number;
  confidence: 'high' | 'medium' | 'low';
  evidenceIds: string[]; // required, non-empty
  source: 'manual_note' | 'commit_message' | 'llm_extracted';
  userConfirmed: boolean;
}

interface Outcome {
  id: string;
  contextId: string;
  kind: 'fix_implemented' | 'pr_opened' | 'pr_merged' | 'abandoned' | 'blocked' | 'unresolved';
  describedAt: number;
  evidenceIds: string[];
  confidence: 'high' | 'medium' | 'low';
}
```

An LLM-extracted decision starts `userConfirmed: false` and is shown as a _proposal_, not a fact. This
is §78 and §79 made structural: the model cannot promote its own guess to a memory.

## 12. Retention and compaction by layer

| Layer                  | Default retention | On expiry                                        |
| ---------------------- | ----------------- | ------------------------------------------------ |
| `TimelineEvent`        | 90 days (A-4)     | Compacted into activities, then deleted          |
| `Activity`             | 1 year            | Compacted into contexts, then deleted            |
| `Session`              | 1 year            | Deleted; durations already rolled into contexts  |
| `Context`              | Forever           | Never auto-deleted                               |
| `ContextLink`          | Forever           | Never auto-deleted — this is the evidence (TR-5) |
| `Decision` / `Outcome` | Forever           | Never auto-deleted                               |
| `manual.*` events      | Forever           | Exempt from compaction                           |

**Compaction contract:** compaction may reduce volume but may never remove a _citable identifier_. A
commit SHA, a file path, a URL, a command string or a timestamp that appears in a `ContextLink` survives
indefinitely. That contract is what keeps §114's six-months-later question answerable.

## 13. Validation

Runtime validation is mandatory (§21), at three points:

1. **At ingest** — untrusted producers. Schema check, type check, pause check, incognito assertion,
   clock-skew check (reject timestamps more than 5 minutes in the future).
2. **Before persistence** — internal invariants: redaction stamp present, `searchableText` produced by
   the normaliser, importance in range.
3. **On read into the context engine** — defensive, cheap; a malformed row is skipped and logged rather
   than crashing a background job.

Schemas live in `packages/protocol/schemas/*.json`; Rust types are generated at build time, TypeScript
types at `pnpm codegen`. Hand-written duplicates of these types are a review-blocking error.
